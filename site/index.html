Firebase project check

Check your Firebase project before a deploy.

For Firebase developers who need to catch wrong projects, sign-in issues, emulator mismatches, or missing rules files before changing cloud data.

How it works

How to check a Firebase project

Start with local files. Add the network check only when you need Firebase access confirmed.

  1. 01 / LOCAL

    Run the local check

    Open a Firebase project directory and run:

    firebase-environment-doctor
  2. 02 / RESULTS

    Read the project and file results

    Confirm the selected project. Then follow the next check for each finding.

    {{FIREBASE_DOCTOR_WORKFLOW_EXCERPT}}
  3. 03 / OPTIONAL

    Choose the optional network check

    Use this only when you want the tool to check Firebase access.

    firebase-environment-doctor --network

What it checks

Check five Firebase settings.

The tool reads your project files and Firebase CLI results. It tells you what to check next.

  1. 01 / PROJECT

    Selected project

    Finds the project chosen by your command, environment, or project file.

  2. 02 / SIGN-IN

    Firebase access

    Checks local sign-in details. With --network, it checks Firebase access.

  3. 03 / EMULATORS

    Emulator addresses

    Compares emulator addresses with firebase.json.

  4. 04 / RULES

    Rules files

    Checks that configured rules files exist.

  5. 05 / FIREBASE CLI

    Firebase CLI installed

    Checks Firebase is installed. With --network, it checks project access.

Install

Install the Firebase project check.

Build it from this project source, then run it from a Firebase project directory.

cargo install --git https://github.com/B-Divyesh/sf-firebase-environment-doctor

Use --json for scripts. Use --network to check Firebase access. Use --demo for the bundled sample.
